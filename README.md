# Lead intake — n8n workflow

Сценарий автоматизации на n8n: принимает заявку по webhook, проверяет и нормализует данные,
уведомляет администратора в Telegram и сохраняет заявку во встроенную таблицу n8n (Data Table).

```
POST /webhook/lead-intake
        │
        ▼
 Validate & normalize ──► Valid? ──yes──► Telegram (уведомление) ──► Data Table (строка) ──► 200 {status, id}
  (Code node)                 │
                              └─no────► 400 {status: "error", errors: [...]}
```

## Что делает

- **Webhook** принимает `POST` с JSON `{ name, phone, message, source }` — например, из формы на сайте или из бота.
  Доступ защищён токеном в заголовке `X-API-Key` (Header Auth): без него или с неверным — `403`.
- **Валидация** (Code node): имя ≥ 2 символов, телефон 10–15 цифр (приводится к виду `+79991234567`),
  сообщение ≥ 3 символов; российский `8…` превращается в `+7…`. Каждой заявке присваивается `id` и время создания.
- **Невалидная заявка** получает ответ `400` со списком ошибок, ничего не сохраняется.
- **Валидная заявка**: сообщение админу в Telegram → строка в таблице `leads` → ответ `200` с `id` заявки.
- Узлы Telegram и Data Table настроены так, что сбой одного из них (нет доступа, лимит) не роняет весь сценарий
  и заявитель всё равно получает ответ.

## Запуск

Нужен Node.js 20+.

```bash
npm install          # ставит n8n локально
npx n8n              # UI на http://localhost:5678
```

Импорт сценария: в UI → **Workflows → Import from file** → `lead-intake.workflow.json`.

Настроить в UI (значения в файле — заглушки):

1. **Telegram**: создайте credential с токеном бота от @BotFather; в узле замените `YOUR_TELEGRAM_CHAT_ID`
   на id чата администратора.
2. **Data Table**: в n8n откройте **Personal → Data tables → Create**, назовите таблицу `leads` и добавьте
   колонки (тип string): `leadId`, `submittedAt`, `name`, `phone`, `message`, `source`.
3. **Токен webhook**: в узле Webhook создайте credential **Header Auth** — имя `X-API-Key`, значение — любая
   случайная строка (например, `openssl rand -hex 16`).
4. Нажмите **Publish**.

## Проверка

Валидная заявка:

```bash
curl -X POST http://localhost:5678/webhook/lead-intake \
  -H 'Content-Type: application/json' -H 'X-API-Key: <ваш токен>' \
  -d '{"name":"Иван","phone":"+7 (999) 123-45-67","message":"Хочу бота для салона","source":"site"}'
# → {"status":"ok","id":"L..."}
```

Невалидная:

```bash
curl -i -X POST http://localhost:5678/webhook/lead-intake \
  -H 'Content-Type: application/json' -H 'X-API-Key: <ваш токен>' -d '{"name":"И","phone":"123","message":""}'
# → 400 {"status":"error","errors":["name: ...","phone: ...","message: ..."]}
```

## Проверено

Локально на n8n 2.39.8: без токена и с неверным токеном — `403`; с верным: валидная заявка → сообщение в Telegram + строка в таблице `leads` + ответ `200`;
невалидная → ответ `400` со списком ошибок, ничего не сохраняется. Кириллица в именах и сообщениях сохраняется корректно.

## Ограничения

- Конвертация `8 → +7` только для 11-значных номеров; номера без кода страны (10 цифр) и международные форматы не разбираются.
- Токен защищает от посторонних, но лимита запросов (rate limit) нет: владелец токена может слать сколько угодно.
- Нет защиты от дублей: повторная отправка создаёт вторую заявку.
- Хранилище — встроенная таблица n8n: подходит для демонстрации и небольших объёмов; для реальной работы лучше CRM или база данных.
- Сценарий рассчитан на одного администратора; маршрутизации по менеджерам нет.
